Type alias ServiceResponseDecodeErrorReason

ServiceResponseDecodeErrorReason: "unsupported-encoding" | "no-schema" | "schema-mismatch" | "malformed"

Why a service response could not be read:

  • 'unsupported-encoding': the server answered in an encoding this client does not decode (for example protobuf, from a Foxglove SDK server).
  • 'no-schema': neither the server nor the schemas bundled with this library describe the response type.
  • 'schema-mismatch': the server described the response type as having no fields, but the response carries data, so the description was wrong.
  • 'malformed': the payload could not be parsed in its declared encoding, or against the schema found for it, or parsed to something that is not a response record (a JSON null, number, string or array). A zero-length payload lands here when a schema was found for it: even a response with no fields serializes to a few bytes, so an empty one was lost or broken on the way. With no schema at all it is 'no-schema', as any payload would be; bytes is then empty.

This union may gain members in future releases; branch with a default case.
